Ouvrez un fichier CIOPRG.LST

Utilisez 📂 Ouvrir (chemin par défaut), Parcourir…, ou glissez-déposez le fichier ici.
Le fichier se sauvegarde depuis le pupitre : EX. MEMORY → SAVE → I/O DATA → C.IO PGM.

Chargez un fichier pour commencer.

Mode d'emploi

  • Ouvrir : le bouton 📂 essaie d'abord le chemin par défaut (fichier ou dossier), puis le dernier dossier ou fichier choisi (mémorisé par le navigateur). Pour des raisons de sécurité, un navigateur ne peut pas lire un chemin du disque sans votre accord : au premier usage il vous demande de choisir le dossier, puis le rouvre en un clic.
  • Noms de signaux : « 📁 Dossier… » ouvre un dossier de sauvegarde et lit CIOPRG.LST et, s'ils sont présents, IONAME.DAT (entrées/sorties générales), EXIONAME.DAT (entrées/sorties externes), IOMNAME.DAT (registres M) et tout fichier .CSV au format #70017;Nom. On peut aussi les sélectionner ensemble avec « Parcourir… ». Les noms s'affichent sous les contacts et bobines ; un nom personnalisé (relais auxiliaires…) peut être saisi dans le panneau et reste enregistré dans le navigateur.
  • Recherche globale d'un signal : tapez une adresse (#70017, 70017, IN12, OUT3, M479) ou une partie de nom, puis Entrée. Le panneau liste chaque rung qui l'écrit ou le lit, avec l'instruction ; ◀ ▶ (ou F3 / Maj+F3) passent d'une utilisation à l'autre, « ces rungs » masque les autres. Cliquer un contact lance aussi la recherche.
  • Comparer : « ⇄ Comparer… » charge un second CIOPRG.LST (B) et liste les rungs identiques, modifiés, absents ou ajoutés, côte à côte, avec les lignes différentes surlignées. Chaque écart peut être repris : remplacer par B, insérer dans A, supprimer de A. Les rungs concernés sont marqués dans la vue.
  • Glisser un contact : faites glisser un contact sur un autre élément : moitié gauche = en série avant, moitié droite = en série après, bas = en parallèle. Maintenez Ctrl (ou Alt) pour copier au lieu de déplacer. Fonctionne aussi d'un rung à l'autre.
  • Couper / copier / coller : Ctrl+X, Ctrl+C, Ctrl+V (ou les boutons) sur les rungs sélectionnés ; le collage se fait après le rung actif. Le texte copié est la liste d'instructions : on peut coller entre deux onglets ouverts sur deux fichiers, ou depuis un éditeur de texte.
  • Sélection : cliquez sur l'en-tête d'un rung (ou sa case), Maj+clic pour une plage, ou filtrez puis « Sélect. visibles ». Le filtre accepte une adresse (#40010), un mot (TMR) ou une plage de sorties (40010-40237).
  • Tri : choisissez le critère puis ↑ / ↓ pour réordonner les rungs sélectionnés : n° du premier relais de sortie, type de sortie (OUT, PLS, GOUT, BMOV…) puis n°, n° de la première entrée, nom de la sortie, taille du rung, ordre d'origine du fichier, ou dépendances (un rung qui écrit un signal passe avant ceux qui le lisent, en conservant au mieux l'ordre actuel ; le nombre de lectures avant écriture est affiché avant/après). Les rungs triés reprennent les emplacements occupés par la sélection. Tri manuel : glisser la poignée ⋮⋮, ou ▲ ▼. Le tri reste à l'intérieur d'une même PART.
  • Édition graphique : cliquez sur un contact, une bobine ou un bloc pour le modifier dans le panneau (adresse, contact inversé, insertion en série ou en parallèle, suppression). Ctrl+clic sur plusieurs contacts consécutifs en série pour les mettre en parallèle avec une nouvelle branche. Le bouton IL d'un rung permet aussi de l'éditer en texte. Ctrl+Z / Ctrl+Y pour annuler / rétablir.
  • Sauvegarde : avec le dossier de sauvegarde complet, « 🗂 Sauvegarde » présente : l'historique des alarmes (ALMHIST.DAT, codes les plus fréquents), les alarmes et messages utilisateur pilotés par le ladder (relais #79700–#79777 = alarmes 1–64, codes 9064–9127 ; #79810–#79887 = messages 1–64) avec les rungs qui les déclenchent, les textes //ALARM et //MESSAGE de CIOPRG.LST (modifiables), le panneau d'interface (fichier contenant //IFPANEL : grille 1A–4H, couleurs, signaux affichés et commandés), les jobs *.JBI (lignes qui lisent ou écrivent des E/S) et SYSTEM.SYS. La recherche de signal liste aussi ces utilisations « hors ladder ».
  • Export : « Modifications » récapitule les rungs ajoutés, modifiés, déplacés ou supprimés ; « Exporter .LST » produit le nouveau fichier. Le contrôleur ne charge qu'un fichier nommé CIOPRG.LST.

Fonctionnement et sources

Fonctionnement

  • Lecture : CIOPRG.LST est lu octet par octet et découpé en rungs ; la liste d'instructions à pile (STR, AND, OR, AND-STR, OR-STR…) devient un arbre série/parallèle dessiné en SVG.
  • Export : rungs non modifiés, en-tête, textes d'alarmes, fins de ligne et encodage recopiés à l'identique ; un rung modifié est recompilé depuis l'arbre puis relu pour validation.
  • Tri : critère au choix sur la sélection, dans une même PART ; « dépendances » = tri topologique (un rung qui écrit un signal passe avant ceux qui le lisent).
  • Comparaison : plus longue sous-suite commune des rungs normalisés, puis appariement des rungs restants de même sortie (« modifiés »).
  • Noms : le n-ième nom d'IONAME.DAT / EXIONAME.DAT est associé au n-ième signal (n°1 = #x0010, n°9 = #x0020).
  • Sauvegarde : ALMHIST.DAT (code et date repérés automatiquement), IF panel (//IFPANEL, 23 champs), jobs *.JBI (IN#, OT#, IG#, OG#, SIN#, SOUT#), SYSTEM.SYS.
  • Confidentialité : tout le traitement se fait dans le navigateur, aucun fichier n'est envoyé.

Sources de données

  • Aucune donnée externe ni bibliothèque : seuls les fichiers que vous ouvrez sont lus.
  • Format du ladder : YRC1000 Concurrent I/O (RE-CKI-A467), Concurrent I/O Overview, Ladder Editor (HW1483388), exemple réel.
  • Fichiers de noms : Yaskawa 159584-1CD, Robot-Forum, exemple IONAME.DAT.
  • Alarmes : Yaskawa User Alarms, User Messages, Handling Alarms, MotoLogix.
  • IF panel : DX100 Interface Panel Function (156443-1CD), chapitre 5.

Limites

  • PART 1 est supposée système (verrouillée) et PART 2 utilisateur ; CMP et instructions rares restent affichées en texte.
  • Trier ou déplacer peut décaler d'un cycle un relais interne ; le tri par dépendances ignore BMOV, ADD, MOV… et les boucles volontaires.
  • Formats d'ALMHIST.DAT et des fichiers de noms non publiés : vérifiez quelques noms et codes sur le pupitre.
  • Plages #797xx / #798xx (alarmes / messages utilisateur) et SIN# / SOUT# → #4xxxx / #5xxxx : DX100, DX200, YRC1000 uniquement.
  • Pas de contrôle de compatibilité avec l'application du contrôleur : un fichier mal construit est refusé au chargement.
  • Un navigateur ne lit pas un chemin du disque sans accord : le dossier doit être choisi une première fois.
